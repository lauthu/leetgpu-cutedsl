# Matrix Transpose

[LeetGPU 题目](https://leetgpu.com/challenges/matrix-transpose) · challenge 3 · 官方定义 `3_matrix_transpose` · 语言 `cute`

## 题目

`input`（`rows × cols`）和 `output`（`cols × rows`）是 GPU 上按行存放的 `float32` 矩阵。计算转置，`output[j][i] = input[i][j]`，结果直接写入 `output`。约束为 `1 ≤ rows, cols ≤ 8192`。

- 性能测试：`rows = 7000`，`cols = 6000`，取值在 −10 到 10 之间
- 判定：`atol = 1e-05`，`rtol = 1e-05`

## 评审

标"自测"的数字不是提交记录。它们是在平台的 H100 上用附在 `make run` 里的脚本量的：尺寸 7000 × 6000，在同一个进程里重复调用已经编译好的函数，取中位数；脚本不在仓库里。

### 结论

- **H100 现状：** v1 的 0.26903 ms 是 CuTe 的第 1 名，第 2 名是 0.3454 ms，慢 28.4%，超过假定的 5% 波动。只有一次提交，v2 还没有提交，所以没有版本之间的比较。

### 代码

- `v1.py:47-49` **未验证**：smem 的行步长是 `BN + 1`，为的是一个 warp 读一列时落在 32 个不同的 bank 上（推断，按地址算的，没有量过）。v1 的输出拷贝一个 warp 读的是 4 行 × 8 列，并不是一列，所以这个填充在 v1 里没有完全起作用；v2 里一个 warp 正好读一列。
- `v1.py:38-46` **可读性**：文件里留着修改过程的注释（`# FIX`、`# was:`，还有第 69-87、96-103 行）。它已经提交，所以是冻结的。下一版：v2 是不带这些注释的写法。
- `v1.py:9-29` **多余**：每个 tile 都计算谓词，包括完全在矩阵内部的 tile。自测里让完整的 tile 不带谓词，时间没有变化（0.138–0.139 ms），所以不值得为它多一条分支。
- **做得好的：** 转置写在 layout 里：`Bt` 是输出按列读的视图（`v1.py:104-106`），内核只是把 `A(i, j)` 拷到 `Bt(i, j)`。官方 12 个功能用例里 11 个比一个 tile 小，另一个是 8192 × 8192，完整和不完整的 tile 都被检查过，走的是同一条路径；示例 2 × 3 也是，所以 `make run` 就能测到内核。

### 性能机会

**H100：** 单次结果低于 0.25558 ms 才算比 v1 快。空间（推断）：v1 的自测是 0.170 ms，提交是 0.26903 ms，约 0.1 ms 在内核之外，原因未知。内核之内，v2 的 0.139 ms 里启动和同步占 0.020 ms，读 168 MB 占 0.055 ms，写占 0.060 ms，各约 3 TB/s；H100 的内存带宽大约是 3.35 TB/s（凭记忆，没有核对），内核里剩下的余地很小。

1. **提交 v2**（文件已经写好）：v1 的输出拷贝让线程号沿 j 递增（`v1.py:62-64`），一个 warp 的一次写落在 8 处，每处 4 个 `float32`。v2 让线程号沿 `Bt` 连续的 i 递增，一个 warp 写 32 个相邻的值。依据：自测里交替量了 4 轮，v1 是 0.169–0.171 ms，v2 是 0.138–0.139 ms。如果内核之外的 0.1 ms 不变，提交大约是 0.24 ms（推测）。
2. **弄清内核之外的 0.1 ms**（一次 `run`，不是提交）：平台每次计时都用新生成的输入，并先清 L2 cache；自测重复用同一对缓冲区。实验：自测里每次调用都新建输入和输出。多出来的时间出现了，就说明访存的顺序和 tile 的形状还可以再试；没有出现，那是调用本身的开销，这道题就到头了。
3. **不值得花配额的三项**：128-bit 的读取（读已经约 3 TB/s，上限约 0.005 ms）、更大的 tile（自测 64 × 64 是 0.139 ms，128 × 128 是 0.158 ms）和把边界 tile 移出内核（见代码评审的第三条）。

## 版本

### v1 · Staged（`v1.py`）

把两块内存包成坐标相同的两个视图：`A(i, j)` 是 `input[i][j]`，按行存放；`Bt(i, j)` 是 `output[j][i]`，也就是把输出按列读。内核只做 `Bt(i, j) = A(i, j)`。一个 CTA 用 256 个线程处理一个 32 × 32 的 tile，先 gmem → smem，再 smem → gmem，这样两边可以各自沿连续的方向访问；两次拷贝都带谓词，跳过矩阵之外的元素。

### v2 · Coalesced（`v2_coalesced.py`，未提交）

与 v1 只差一处：输出拷贝的线程号沿 i 递增，一个 warp 写 `Bt` 里相邻的 32 个值。自测在 12 个尺寸上结果都正确，从 1 × 1 到 8192 × 8192。还没有提交，所以不在结果表里。
