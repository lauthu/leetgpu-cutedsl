# Color Inversion

[LeetGPU 题目](https://leetgpu.com/challenges/color-inversion) · challenge 7 · 官方定义 `7_color_inversion` · 语言 `cute`

## 题目

`image` 是 GPU 上的一维 `uint8` 数组，长度 `width × height × 4`，每 4 个字节是一个像素的 R、G、B、A。把 R、G、B 各换成 `255 − 值`，A 不变，结果原地写回。约束为 `1 ≤ width, height ≤ 4096`，`width × height ≤ 8,388,608`。

- 性能测试：`width = 4096`，`height = 5120`，取值在 0 到 255 之间；20,971,520 个像素，超过题面写的上限
- 判定：`atol = 1e-05`，`rtol = 1e-05`

### 结论

- **H100 现状：** 最好成绩是 v1 的 0.17937 ms，CuTe 的第 1 名；第 2 名 0.26959 ms 是它的 1.50 倍（0.26959 ÷ 0.17937）。最新的 v2 是 0.24444 ms，也低于第 2 名。
- **H100 版本之间：** 按提交记录，v2 比 v1 慢 36.3%，超过假定的 5% 波动；两次提交相隔 46 秒。这与自测对不上：v2 的做法在自测里是 0.0765–0.0817 ms，已经在内存带宽附近（见性能机会），v1 在内核里不可能比它快多少（推断）。v1 没有自测数字，它在自测那次 run 里还编译不过。所以多出来的时间在内核之外（推断），原因未知。[Matrix Addition](../8_matrix_addition/README.md) 出现过同样的情况。

### 代码

- `v2_words.py:84-87` **测试覆盖**：平台的缓冲区是对齐的，只保证 1 字节的分支官方测试走不到。自测里把缓冲区错开 1 个字节，5 × 3 和 999 × 1000 的结果正确，图像前后的保护字节没有被改写。
- `v2_words.py:60-71` **测试覆盖**：官方 7 个功能测试的像素数是 4、1、12、15、4、4096、2048。整组的路径、尾部（1 和 15 个像素）、多个 block（4096 个像素是 4 个 block）都被走到。
- `v1.py:16-17` **多余**：`tI` 和 `tO` 是同一个视图，原地操作只需要一个名字。v2 已经改掉。
- `v1.py:18` **可读性**：`(VALUES)` 不是 tuple，只是 `4`。`make_rmem_tensor` 接受它；`local_tile` 不接受，写成 `cute.local_tile(image, (VALUES), pixel)` 时编译器报 `coord` 与视图的形状不一致，要写 `(VALUES,)` 和 `(pixel,)`。
- **做得好的：** 一个像素读成一个小端的 32-bit 字，R、G、B 是低三个字节，取反并保留 A 就是一次 `word ^ 0x00FFFFFF`（`v2_words.py:64`）。对齐的声明有实测依据：只保证 1 字节时慢到 3 倍，4 字节和 16 字节没有差别，所以只声明 4 字节（`v2_words.py:84`）。

### 性能机会

**H100：** 单次结果低于 0.23222 ms 才算比 v2 快；最好成绩是 v1 的 0.17937 ms。空间：图像 83.9 MB（20,971,520 × 4 字节），读一遍、写一遍共 167.8 MB。v2 的做法在自测里约 0.078 ms，扣掉 [Matrix Transpose](../3_matrix_transpose/README.md) 的自测量到的启动和同步 0.020 ms，是 167.8 MB ÷ 0.058 ms ≈ 2.9 TB/s，与另外两道题量到的速率相当，内核里没有余地（推断）。v2 的提交比自测多出 0.165 ms（0.24444 − 0.079），这一部分在内核之外。

没有值得花配额的机会。自测里每线程 4 个和 8 个像素没有差别，16 个更慢。提交之间差的是内核之外的部分，改内核改变不了它。建议把配额留给下一道题。

## 版本

### v1 · Per pixel（`v1.py`）

每个线程处理一个像素：把它的 4 个字节当作一个小 tile 读进寄存器 Tensor，前三个字节各换成 `255 − 值`，再整个写回。block 为 256 个线程，线程号超出像素数的不做事。这一版是第一个 `uint8` 的内核。

### v2 · Words（`v2_words.py`）

把图像看成每个像素一个 32-bit 字，取反就是一次 XOR。每个线程拥有 4 个连续的像素：整组在图像内就一次 `load()`、XOR、`store()`，否则逐个处理并检查越界；线程数是 v1 的四分之一。`solve` 检查地址，是 4 的倍数时向编译器声明 4 字节对齐，否则用同一个内核、不带这个声明。
